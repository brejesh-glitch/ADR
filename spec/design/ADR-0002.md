# Implement Dynamic Theme Color Derivation using chroma-js

## Context

Previously, the calculator application's UI theme colors (base, dark, light, lighter shades for various states like hover and active) were manually defined as distinct hexadecimal values in `style.css`. When a theme color needed to be changed, all related shades had to be manually re-calculated and updated, which was a tedious, error-prone, and time-consuming process. This approach made theme customization and maintenance difficult, hindering flexibility and consistency.

## Decision

To address the challenges of manual theme color management, the application adopts a dynamic theme color derivation strategy using the `chroma-js` JavaScript library.

1. **Dependency Introduction:** `chroma-js` is added as a dependency in `package.json` for documentation. At runtime, it is loaded directly via a CDN (`https://cdn.jsdelivr.net/npm/chroma-js@2.4.2/chroma.min.js`) in `index.html` to avoid introducing a build step for this simple application.
2. **Runtime Derivation Logic:** A new function, `applyDerivedTheme()`, in `script.js`:
   - Reads the `--theme-base` CSS custom property from the document's root element.
   - Uses `chroma-js` to programmatically derive `--theme-dark`, `--theme-light`, and `--theme-lighter` shades from `--theme-base` (`darken(1.4)`, `brighten(0.8)`, `brighten(1.6)`).
   - Applies these derived values as CSS custom properties on `document.documentElement`, overriding the initial values.
3. **CSS Fallback:** Hardcoded initial values for `--theme-base`, `--theme-dark`, `--theme-light`, and `--theme-lighter` remain in `style.css` as fallbacks in case the `chroma-js` CDN script fails to load or JavaScript is disabled, so a static theme is always present.
4. **Theme Definition:** The primary theme color is now controlled by a single `--theme-base` CSS variable, making theme changes a one-line edit.

## Alternatives Considered

- **Manual CSS variable updates:** keep defining all shades by hand in `style.css` — no new dependency, but high maintenance burden and prone to inconsistency.
- **CSS preprocessor (Sass/Less):** derive shades at build time from a base color — automated and dependency-free at runtime, but introduces a build step this app explicitly avoids.
- **Pure CSS color functions** (`color-mix()`, HSL/RGB math): no JS dependency, but more limited for perceptual darken/brighten and less consistent results than a dedicated library.
- **Full theming library/framework:** more capability, but significant overkill and overhead for a simple calculator.

## Consequences

**Positive**
- Changing the entire theme now requires updating only `--theme-base`, drastically simplifying future theme changes.
- Derived shades keep a consistent, predictable relationship to the base color instead of being hand-tuned per theme.
- Removes manual recalculation of multiple hex values per theme change.

**Negative**
- Adds `chroma-js` as an external dependency loaded via CDN — a potential point of failure (CDN outage) and a small addition to page load.
- The dynamic theme relies on JavaScript execution; if JS is disabled or the CDN fails, the app falls back to the hardcoded CSS values, which may not match the intended theme.
- Slightly increases codebase complexity with the new derivation logic.
- Possible brief flash of the fallback theme before `chroma-js` applies derived colors, if the CDN script loads late — considered acceptable for this simple app.
