# Add A-ADR MCP agent for automated Architecture Decision Records

## Context

The process of documenting architectural decisions through Architecture Decision Records (ADRs) is crucial for maintaining a clear understanding of system evolution and rationale. However, manually drafting ADRs can be time-consuming and may lead to inconsistencies in format or completeness. To streamline this process and ensure that architectural decisions are captured promptly and consistently, there is a need for an automated mechanism to assist in ADR generation. This automation should leverage modern AI capabilities to synthesize ADRs from development artifacts, specifically Pull Request (PR) information.

## Decision

We will implement an automated agent, named "A-ADR Architecture Agent," to draft Architecture Decision Records (ADRs) based on Pull Request (PR) context.

1. **Agent Framework:** The agent is built as a `FastMCP` server, exposing a `synthesize_adr` tool. This choice provides a lightweight and efficient framework for exposing an ADR-drafting capability that other agents/hosts can call directly.
2. **AI Model:** The `synthesize_adr` tool is backed by the `Gemini 2.5 Flash` model from Google GenAI, selected for its balance of performance, cost-effectiveness, and capability in structured text generation.
3. **Input and Output:** The tool accepts the PR title, description, and git diff as input, and generates a formal ADR in Markdown format, following the standard Title / Context / Decision / Alternatives / Consequences schema.
4. **Do-Not-Delegate Rule Compliance:** All generated ADRs explicitly start with `status: draft`. A human reviewer is responsible for reviewing, refining, and formally accepting the ADR — the agent formalizes decisions already made in a PR, it does not originate them.
5. **Dependencies:** New project dependencies `fastmcp` and `google-genai` are added to `requirement.txt`.
6. **Binary Management:** The `bin/` directory (vendored `github-mcp-server` binary) is now git-ignored rather than tracked, since it is a downloaded release artifact, not source.

## Alternatives Considered

- **Manual ADR creation:** keep writing all ADRs by hand — full human control, but prone to inconsistency, delay, and being skipped under time pressure.
- **A different LLM** (OpenAI GPT, other Gemini tiers, open-source models): rejected in favor of Gemini 2.5 Flash for its speed/cost/quality balance on this drafting task.
- **A different server framework** (Flask/FastAPI/custom HTTP): rejected in favor of FastMCP, which is purpose-built for exposing agent tools over MCP.
- **Full automation without a `draft` gate:** rejected outright — violates the Do-Not-Delegate rule, which requires a human to accept any new architectural pattern.

## Consequences

**Positive**
- Reduces manual effort to initiate ADRs and standardizes their format.
- Lowers the barrier to documenting decisions, encouraging more complete coverage.
- Human oversight is preserved via the mandatory `draft` status.

**Negative**
- Adds `fastmcp` and `google-genai` to the dependency surface.
- Introduces an external-service dependency on Google's GenAI API (cost, uptime, key management).
- Drafts may contain inaccuracies and always require human review before acceptance.
